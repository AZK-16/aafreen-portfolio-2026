Building a Time Capsule Notes App with Claude Code

The Outcome
How I learned to design and build faster with Claude, iterating on the interface and functionality through AI-assisted prototyping, prompting, debugging and testing.

Domain: Productivity / Personal Reflection
Time to Results: 3 days

Make a Time Capsule View LinkedIn Post
2 Context

For this project, I challenged myself to take an idea from concept to functional product within 1 week using AI-assisted development and my own frontend knowledge.

3 Challenge

Use the project to develop 3 key areas:

Rapid Prototyping
Learn how to work effectively with Claude Code and improve my prompt engineering.
App Design
Explore how to turn an idea into a clear, personalised and responsive interface.
Development & Testing
Build and debug a working application while understanding the code AI generated.
4 Workflow
Concept Wireframe Prompt Build Test Iterate

I used different AI tools at different stages of the process rather than relying on one prompt to generate the entire app.

4.1 Prototyping

I first explored the app structure through an HTML wireframe, giving me a visual starting point before asking Claude Code to build the functional version.

Why?
Starting with a wireframe gave me something concrete to evaluate and helped communicate the intended structure to Claude Code.
4.2 Prompting

I found that specific instructions produced more predictable results.

Instead of
“Make the notes section better”
I described
User interactions and expected system responses
Where the change should appear
How it should look

For example, when implementing deleted notes, I described the exact interaction and placement of the new section in the prompt:

when the delete icon is clicked, could you please delete the note from the list but place that note in a ‘deleted notes’ section after the notes list section that looks like

DELETED NOTES <rubbish bin icon>
4.3 Building

While building, I kept the app running on localhost so I can quickly identify missing elements, bugs and visual issues while making changes.

5 AI Design Challenges
5.1 Specificity Matters

One of the biggest lessons was that AI can interpret visual and spatial instructions very differently depending on how specifically they are described.

Less specific
“Move the box to the right.”
More specific
“Vertically centre the box within the right-hand section.”
Less specific
“The blue box”
More specific
“Hex code #4A5FC4”
5.2 Testing & Troubleshooting

As the app developed, I used iterative testing to identify issues rather than waiting until the end.

Method 1
Breaking Problems Down
When multiple things were wrong, I listed them separately e.g.
1Issue with note deletion
2Issue with date selection
3Issue with responsive layout
Why?
This helped prevent Claude from treating several unrelated problems as one.
Method 2
Visual Debugging
Screenshots were particularly useful for communicating what was visually wrong and what I wanted changed. Localhost allowed me to view and evaluate updates in real time.
5.3 Tracking Changes

While development with Claude was largely reliable, I learned that AI-generated solutions still need to be evaluated against the exact system response I intended.

Small Changes
I made and tested changes incrementally rather than asking Claude to modify large parts of the application at once.
Git Checkpoints
I committed changes to Git after significant updates, giving me a reliable checkpoint to return to if an AI-generated change caused unexpected issues.
Manual Changes
Sometimes the best solution was to edit the code myself and then tell Claude what I had intentionally changed.
Why?
This helped me stay in control of the codebase rather than blindly accepting every AI-generated solution.
6 Project Reflection
Reflection
What I Learned
Specificity improves results
The more context I gave Claude about the user’s actions, interface structure and desired outcome, the fewer iterations were needed.
AI works best iteratively
I learned to treat AI as a collaborator rather than a one-shot solution: prompt → evaluate → test → refine.
Understanding the output matters
Rather than simply accepting generated code, I used Claude to explain unfamiliar code and concepts line-by-line, helping me understand why a solution worked.
Improvements
What I’d Do Differently Next Time
More personalised visual design
Plan dark mode earlier to reduce iterations
